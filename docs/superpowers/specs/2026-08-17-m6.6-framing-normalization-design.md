# M6.6 — Resolution-Independent Framing (Scale Normalization) — Design Spec

> Status: owner-approved direction (2026-08-17), made developer-ready · Sibling to
> M6/M6.5 in the export family; standalone milestone **M6.6** between M6.5 and M7.
> Scope decision (owner): applies to the **flock archive AND one-shot export**;
> `animate` (the byte-exact mastering path) and the render engines stay faithful.
> Legacy archive handling (owner): a full wipe + regenerate is acceptable — but a
> version gate is added anyway (cheap, existing pattern) so a wipe is optional.
>
> Roadmap: `docs/engineering/roadmap.md` §M6.6 (slice S10.6).

## 1. Motivation — the owner's observation

Generating the same genomes at different shard resolutions showed systematic
framing drift: **720p reads "too zoomed in", 1080p "slightly zoomed in", 1440p
"optimal", 4K "too zoomed out."** This is not a rendering bug — it is a property
of the flame data model colliding with resolution-independent rendering.

## 2. Root cause analysis

### 2.1 `scale` is absolute pixels-per-unit

A `.flam3` genome carries `camera.scale` = **pixels per unit of fractal space**
(an absolute pixel count, not a relative zoom) plus `size` = the canvas it was
authored for. Emberweft (faithfully to flam3) uses it verbatim:

```
ChaosGame.swift:107     pixelsPerUnit = flame.camera.scale * pow(2, zoom) * oversample
```

with **no normalization by output size**. So the fractal occupies the *same
number of pixels* at every output resolution while the frame grows: subject
fraction of frame ∝ `scale / frameHeight`. Across the shard ladder 720p→4K that
is a **3× framing change** — the resolution picker currently doubles as a zoom.

### 2.2 The archive is multi-population

gen-248 (all 9,463 sheep) was authored at **three** sizes:

| Authored `size` | n | aspect | median `scale` | median `scale/W` | median `scale/H` |
|---|---|---|---|---|---|
| 800×592  | 7,373 (~78%) | 4:3    | 260.5 | **0.326** | 0.440 |
| 1280×720 | 1,478 (~16%) | 16:9   | 426.5 | **0.333** | 0.592 |
| 1920×1080 | 478 (~5%)   | 16:9   | 633.4 | **0.330** | 0.587 |

### 2.3 The authoring anchor is WIDTH (the key empirical finding)

`scale/width` is consistent to within **2%** across all three populations
(pooled median 0.329), while `scale/height` differs by **34%**. Electric Sheep's
authoring + vote-based evolution kept the **horizontal** framing constant across
its entire history (including the 4:3→16:9 transition). The earlier apparent
inconsistency between the 800×592 and HD populations was purely the aspect
change — under width normalization the populations are already mutually
consistent.

### 2.4 Within-population spread is authorial intent

Pooled `scale/W`: p10 = 0.139, p90 = 0.674 — a ~4.8× spread. Some genomes are
deliberate close-ups, others wide shots; ES votes already optimized framing per
genome. **Normalization must not touch this spread** — the authored frame is the
only ground truth for intended extent. There is therefore no content-aware
"optimal fill" in M6.6: optimal = *the authored framing*, made
resolution-independent. (Zero `zoom` attrs exist in gen-248 — `scale` is the
whole story; `rotate` is common but rotationally invariant w.r.t. scale.)

### 2.5 Perception analysis (why width, why multiplicative)

- **Weber-Fechner:** perceived magnification is logarithmic — a correct
  correction must be *multiplicative* (a constant factor in log space), which
  `scale × (renderW / authoredW)` exactly is. A pixel-space (additive)
  correction would over-correct at one end.
- **Horizontal dominance:** the classic flame attractor is wider than tall and
  the ES data (§2.3) confirms the authoring community anchored on width. Width
  normalization preserves horizontal composition exactly; on a 16:9 canvas a
  4:3-authored genome gains ~31% *additional horizontal background* (flames
  decay outward — safe), while its vertical framing tightens by the aspect
  ratio — which is exactly how ES's own HD re-authorings behaved
  (scale/H 0.59 at 16:9 vs 0.44 at 4:3, same scale/W).
- **The owner's "1440p optimal"** was the geometric middle where the un-
  normalized framing error happened to be smallest — an artifact, not a
  property of the algorithm. After normalization every resolution frames like
  the authored canvas.

## 3. The transform

```
effectiveScale = genome.camera.scale × (renderWidth / genome.size.x)
```

- Pure, deterministic (rule #2-safe: scalar arithmetic, no collections).
- Identity (factor 1) when `renderWidth == authoredWidth` — byte-identical to
  faithful rendering in that case.
- Applied **before** any interpolation/plan construction, so transitions blend
  *normalized* endpoints (the existing log-space scale interpolation in
  `GenomeInterpolator` then operates on consistent values).
- Guards: `genome.size.x <= 0` → return the genome unchanged (the parser
  default is 1920×1080; synthetic fixtures carry real sizes);
  `camera.scale` NaN/≤0 → unchanged (data-integrity genomes — same class as
  the NaN-center archive genomes; `isRenderable` already skips most).
- Only `camera.scale` is touched. `center`, `zoom`, `rotation`, everything
  else: verbatim.

## 4. Scope

**In scope:**
- `FlameKit.Framing` — the pure helper (new file, no renderer change).
- `ExportSettings.FramingMode` (`faithful` / `normalized`) threaded through the
  one-shot export path (`buildRenderContext`) and the flock archive
  (`ArchiveRenderer`).
- Product defaults: **normalized** for flock Generate/Stitch and one-shot
  export (GUI + CLI). **Type default stays `faithful`** so raw `ExportSettings()`
  (tests, goldens, resume checkpoints) keeps today's bytes.
- CLI: `export --framing faithful|normalized` (default `normalized`);
  `flock generate|stitch --framing …` (default `normalized`). `animate` gets NO
  flag (always faithful).
- Catalog schema v3: `artifacts.framing` exact hit-gate + `emberweft.framing`
  mdta tag + `rebuild` parsing.
- GUI: export-sheet framing picker (Normalized default / Authored); Flock tabs
  always normalized (no toggle v1).

**Out of scope (follow-ups):**
- Realtime playback windows + library thumbnails (`FlamePlayer`,
  `FacetCache`) — same framing issue at preview sizes; touching them risks the
  player's byte-stability. Natural follow-up slice.
- Content-aware auto-framing / "optimal fill" (rejected: fights authorial
  intent, §2.4).
- A user-tunable global framing bias (e.g. ±½-stop EV) — the data says the
  authored framing already IS the optimum; add only if owner testing disagrees.
- ES `<list>` interchange impact: none (naming unchanged; framing is a render
  concern, not an identity concern).

## 5. Locked decisions

| # | Decision |
|---|---|
| D1 | **Width normalization**: `effectiveScale = scale × renderW / size.x` (§2.3, §2.5). Height/area rejected by the population data. |
| D2 | **`FlameKit.Framing` pure helper** — new file; NO renderer/parity change. Engine dirs stay behaviorally identical (the parity gate's `git diff --name-only main`-style check applies to renderer *behavior*; adding a pure untouched-by-renderer file is allowed, mirroring how `intTrunc` guards landed). |
| D3 | **`ExportSettings.framing: FramingMode`** with **type default `.faithful`** (decoding-backward-compatible: legacy prefs/checkpoints decode as faithful) and **product defaults `.normalized`** at the entry points (GUI sheet, GUI flock, CLI export, CLI flock). |
| D4 | **`animate` never normalizes** — no flag, always faithful. The animate↔export byte-identity pin becomes `animate` ↔ `export --framing faithful`. |
| D5 | **One-shot export applies it in `buildRenderContext`** (the single plan-construction site used by `runJob` / `runLongFormJob` / `runResumableBody` — resume re-normalizes deterministically from re-parsed sources). |
| D6 | **Archive applies it in `ArchiveRenderer`** via a pure `unitFlames` step before plan builders (loops: A; edges: A and B) — covers GUI Generate/Stitch MISS and CLI paths through the existing choke point. Flock is *always* normalized in v1 (no faithful toggle in the GUI; CLI keeps `--framing` for mastering parity work). |
| D7 | **Catalog `framing` exact hit-gate** (like `geom`): `artifacts.framing INTEGER NOT NULL DEFAULT 0` (schema v2→v3 in-place migration; 0 = faithful/legacy, 1 = normalized). Generate + Stitch require `existing.framing == requested`; legacy rows MISS and upgrade-overwrite. Tag `emberweft.framing` mirrors the row (read back by `rebuild`). |
| D8 | **No framing field in the seed or shard name** — framing is a content-generation mode, not identity: same `(shard, key)` re-renders + overwrites in place (the upgrade-overwrite path), so the archive never holds two framings of one unit. |

**All decisions locked (2026-08-17).**

## 6. Invariants preserved

1. **Determinism (rule #2):** normalization is a pure function of
   `(genome, renderWidth)` — same inputs, same frames.
2. **animate↔export byte-identity:** preserved *by construction* — the type
   default is faithful, and the pins run `export --framing faithful`
   (explicitly, since test fixtures are 320×200-authored where normalized ≠
   faithful at 1080p).
3. **Engine parity gates:** `FlameReference`/`FlameRenderer` untouched;
   `FlameKit` gains one pure file no existing path calls with a non-identity
   factor. Golden/parity suites run unchanged.
4. **Seamless stitching:** all units of a stitch share framing (D7 gate);
   within a unit, normalization happens before interpolation so loop↔edge
   boundaries blend consistently.
5. **Resume:** checkpoints store sources + settings; `framing` rides in
   `ExportSettings` (Codable) — a v0.6.0 checkpoint decodes as faithful
   (unknown key ignored) and reproduces its original bytes.

## 7. Architecture

```
FlameKit
  Framing.normalize(flame:renderWidth:) -> Flame        (pure, new)
FlameExport
  ExportSettings.FramingMode + .framing                 (faithful default)
  ExportCoordinator.buildRenderContext:                 flames = framing == .normalized
                                                        ? flames.map { Framing.normalize($0, renderWidth: res.width) }
                                                        : flames
FlameFlock
  ArchiveRenderer.unitFlames(A:B:width:framing:)        (pure; renderLoop/renderEdge use it)
  ArtifactRow.framing + FlockCatalog schema v3 + gate   (Generate + Stitch)
  makeMetadata: emberweft.framing tag
EmberweftCLI
  export --framing (default normalized) · flock … --framing (default normalized)
EmberweftUI / EmberweftGUI
  Export sheet: framing picker (Normalized default / Authored)
  FlockView.archiveSettings: framing = .normalized (both tabs)
```

## 8. Testing strategy

- **FlameKitTests (pure math):** factor identity at authored width; expected
  factor at 4K/720p for each population; guards (size.x ≤ 0, NaN/≤0 scale);
  only `camera.scale` mutated; determinism (same input → equal output).
- **FlameExportTests:** `FramingMode` Codable backward-compat (legacy JSON
  decodes `.faithful`); `buildRenderContext` path — export `--frame N --png
  --framing faithful` byte-equals `animate` (the moved pins, explicit flag);
  default-flag export *differs* from animate on a 320×200 fixture (proves the
  default is normalized and the transform is active); normalized renders at two
  resolutions show equal framing (subject-fraction assertion via a cheap
  bounding-box-of-nonzero-luma check on the CPU path).
- **FlameFlockTests:** `unitFlames` purity/expected factor; catalog v2→v3
  migration; framing gate MISS on a legacy row (framing 0) + HIT after
  normalized re-render; `emberweft.framing` tag round-trip + `rebuild` parse.
- **EmberweftCLITests:** flag parsing (`export`, `flock generate`, `flock
  stitch`), bad value rejected, defaults normalized.
- **EmberweftUITests:** export-sheet default resolves `.normalized`; picker
  flips it; `archiveSettings` sets `.normalized`.
- Gates: `make test-fast` green; engine parity untouched (no behavior change
  under `Sources/FlameReference|FlameRenderer`; `FlameKit` diff is one new pure
  file + the settings field).

## 9. Risks

| Risk | Mitiation |
|---|---|
| Existing byte-identity pins break silently | Pins updated in the same task as the default flip; fixtures (320×200) guarantee normalized ≠ faithful at 1080p, so the pins are load-bearing either way |
| Owner's existing archive mixes framings after upgrade | D7 gate forces MISS→re-render; owner also OK wiping (their call, both paths safe) |
| 4:3-authored genomes feel vertically tight on 16:9 | Matches ES's own HD re-authoring behavior (§2.5); owner A/B during verification; a framing-bias knob is the designated follow-up if needed |
| Normalized framing interacts with `GenomeInterpolator` log-space scale blend | Endpoints normalized before blend → the blend operates on consistent values; covered by the archive seam tests |
