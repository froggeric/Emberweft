# M6.1 — Export Pause/Resume (Developer-Ready Spec)

> Slice 1 of the M6.1 follow-up. A self-contained, parity-neutral feature: make
> a long GUI export (the owner's 3-day, 5-sheep genome-default sequence)
> **pausable and resumable** without losing rendered work. Engine math is
> untouched; this is export-coordinator + view-model + UI plumbing.
>
> Slice 2 (temporal smoothing) is a separate spec — it touches the renderer and
> is gated on an owner divergence flag. Do not conflate.

## 1. Context

**Why this exists.** v0.5.0 shipped the GUI export studio. A genome-default 5-sheep
sequence at 1080p takes **3+ days** (the owner measured it). Today the only
out-of-band control is **Cancel** (per-frame `ExportError.cancelled`, discards the
partial file). There is no way to stop and continue. This slice adds **Pause**
(keep completed work + a checkpoint) and **Resume** (continue from the checkpoint,
byte-for-frame identical), plus **crash recovery** (the checkpoint is on disk, so a
crash/quit mid-export is resumable).

**What's already on `main` (verified — do not rebuild):**

  `public actor ExportCoordinator: ExportCoordinating` with three run paths:
  `run(_:)` (single encoder, `:63`), `runLongForm(_:)` (chunked on **segment** edges
  + passthrough concat, `:129`/body `:366`), `runBatch` (`:101`). All return
  `AsyncThrowingStream`; `cancel()` (`:77`, `async`) flips a `cancelled` flag checked

  `AVMutableComposition` passthrough concat** (`:433–470`) on segment edges.

## 2. Architecture

### 2.1 The resumable path is a third dispatch, parallel to `run`/`runLongForm`

`ExportCoordinator` gains `runResumable(_:checkpointIntervalFrames:resumeFrom:)` +
`pause()`. It mirrors `runLongFormJob`'s chunked-encode + concat, with four
differences:

1. **Chunk boundaries are FRAME-COUNT multiples** of `checkpointIntervalFrames` in
   GLOBAL frames (chunk `i` = global frames
   `[i*interval, min((i+1)*interval, totalGlobalFrames))`). This is safe because the
   resumable path renders via a NEW `renderFramesInterleaved` loop (§4.5) that
   decides repeat-count **per global frame** — so a chunk may span a loop→transition
   boundary without the F2 corruption the EXISTING `renderFrames` repeat>1 path would
   suffer. `checkpointIntervalFrames` defaults to 30 (D1′); tune smaller for finer
   pause granularity (each chunk is one encoder session, so there is a floor below
   which encoder start/finish overhead dominates — ~5–10 frames for ProRes/hardware
   encode; the spec's 5–300 range enforces it).
2. **Deterministic chunk filenames** (`<stem>.emberweft-chunk-%04d.<ext>`, beside
   `out`) instead of UUID, so resume identifies completed chunks by index. Chunks
   persist across pause/resume and crash (NOT in a `defer` that always runs — D6);
   deleted only on success, GUI cancel, and discard.
3. **A checkpoint file** (`<stem>.emberweft-export.json`) rewritten atomically after
   each chunk completes. Resume reads it, verifies schema + sources, skips completed
   chunks, renders the rest, concats all.
4. **Per-frame pause check** in `renderFramesInterleaved` → abandons the in-flight
   chunk (encoder.cancel + temp removed); the checkpoint is NOT updated for it (the
   chunk re-renders from its start on resume — ≤ `interval` frames of re-render, the
   cost of a pause, paid on resume).

**Owner decision (D1′, 2026-08-09): interleaved per-frame loop + frame-count chunks**,
NOT segment-aligned. Segment-aligned chunks (the alternative) would re-render up to
one whole loop segment on resume (~450 frames × ~70 s/frame ≈ 8–9 h on the owner's
heavy genome-default frames). Frame-count chunks at interval=30 cap resume re-render
at ~35 min, while preserving the v0.5.0 loop-repeat render-once speedup (each global
frame rendered once — the cache was never about avoiding re-render within a run, only
about writing the bytes `repeatCount×`) and using LESS memory (no per-segment cache).

```
runResumable(job, interval=30, resumeFrom=nil):
  params/plan/budget  (byte-identical to runJob :141–162; SKIP checkLoopRepeatMemory — no cache)
  cp = resumeFrom.flatMap(read) ?? fresh(job, interval)
  globalRendered = Σ_{i ∈ cp.completed} chunkRange(i, interval, totalGlobalFrames).count
  yield(.rendering, currentFrame: globalRendered, total: totalGlobalFrames)   // seed — no 0-jump
  for chunkIndex in 0..<cp.chunkCount:
      if cancelled: throw .cancelled                    // chunk-top (in-flight chunk untouched; discard is the CALLER's job — D18)
      if paused:    throw .paused                       // chunk-top (in-flight chunk untouched)
      if chunkIndex in cp.completed AND file exists: continue
      range = [chunkIndex*interval, min((chunkIndex+1)*interval, totalGlobalFrames))
      encoder = VideoEncoder(chunkURL(out:, chunkIndex, container:)); start()
      renderFramesInterleaved(plan, …, range, loopRepeatCount:, into:, &globalRendered, total:, yield:)
          on pause (per-frame): encoder.cancel(); rm chunk temp; throw .paused   (cp unchanged)
          on cancel (per-frame): encoder.cancel(); rm chunk temp; throw .cancelled
      encoder.finish()
      cp.completed.insert(chunkIndex); rewrite cp (atomic, sorted keys)
  yield(.concatenating, currentFrame: total, total: total)
  concatChunks(sorted chunk URLs, container:, partialURL: job.partialURL)
  atomic rename partialURL → out
  discardCheckpointAndChunks(out:, container:)           // success cleanup
```

### 2.2 Pause vs cancel vs crash — the out-of-band stops

| Stop | Trigger | Flag | Thrown | Chunk in progress | Completed chunks + checkpoint | VM state |
|---|---|---|---|---|---|---|
| **Cancel** | Cancel button / `coord.cancel()` | `cancelled` | `.cancelled` | discarded (temp removed) | **deleted** (GUI) / kept (CLI SIGINT — D3′) | `.cancelled` |
| **Pause** | Pause button / `coord.pause()` | `paused` | `.paused` | discarded (temp removed, NOT checkpointed) | **kept** | `.paused(out, checkpoint, reason: nil)` |
| **Error (recoverable)** | disk-full / transient encode / `metalUnavailable`-on-resume-probe | — | `.encodeFailed`/`.diskFull`/… | discarded (temp removed) | **kept** | `.paused(out, checkpoint, reason: "<msg>")` (banner offers Resume — D7) |
| **Error (terminal)** | source file hash changed | — | `.checkpointSourceChanged` | — | kept (but unusable) | `.failed("A source genome changed…")` |
| **Crash/quit** | process death | — | — | lost (partial temp) | **kept on disk** | (none) — discovered at next launch via D4 |

`out` is untouched until the final atomic rename on success. A stop never partially
overwrites a good `out`.

### 2.3 Determinism (rule #2) — the resume guarantee

Resume rebuilds `Schedule` + `FramePlan` + `ThreadSeedBudget(baseSeed: params.seed)`
from the checkpoint's recipe + re-parsed flames. `descriptor(for: gf)` is pure O(1),
so global frame `gf` renders to **byte-identical pixels** whether rendered in the
original run, after a pause, or after a crash. The concat stitches
independently-encoded sessions in index order; **frame pixels are deterministic
across pause/resume** (the encoded container is not byte-stable across
machines/sessions — already documented for `runLongForm`; frame-pixel identity is the
pin, not container bytes).

Re-parse faithfulness (D6): each `Source` stores `fileURL` + `flameIndex` + `sha256`.
On resume, re-read + SHA-256 (`CryptoKit.SHA256`, an Apple framework) + compare hex;
on match, `Flam3Parser.parse(bytes)[flameIndex]` → identical `Flame`. A hash mismatch
throws `ExportError.checkpointSourceChanged(index:)` (clear failure, not silent
divergence). The text fallback re-parses `Flam3Serializer.serialize([flame])` and is
pinned for round-trip identity (§9.1) but is weaker than the byte-exact URL path.

### 2.4 Checkpoint lifecycle

```
<pause>           → keep checkpoint + completed chunks; discard in-progress chunk temp
<error (recover)> → keep checkpoint + completed chunks; discard in-progress chunk temp; .paused(reason:)
<resume>          → verify schema + sources; skip completed chunks; render rest; concat; on success delete both
<cancel (GUI)>    → delete checkpoint + ALL chunks
<SIGINT (CLI)>    → KEEP checkpoint + completed chunks (D3′) → `--resume` continues later
<discardPaused>   → delete checkpoint + ALL chunks; clear remembered URL   (static helper, no coordinator — D4)
<success>         → delete checkpoint + ALL chunks; clear remembered URL
<crash>           → checkpoint + completed chunks survive on disk → D4 resume offer at next launch
```

## 3. Data design

### 3.1 `ExportCheckpoint` (NEW — `Sources/FlameExport/ExportCheckpoint.swift`)

`Codable`, `Sendable`, `Equatable`. `Flame` is not `Codable`, so the checkpoint stores
the recipe + source locators.

```swift
public struct ExportCheckpoint: Codable, Sendable, Equatable {
    public let schemaVersion: Int          // == 1; mismatch ⇒ ignored + fresh start (D12)
    // --- recipe (rebuilds ExportJob minus flames) ---
    public let settings: ExportSettings    // already Codable (F1) — encoded directly
    public let framesPerSegment: Int
    public let transitionFramesPerSegment: Int
    public let segmentCount: Int
    public let selector: SelectorSpec
    public let seed: UInt64
    public let loopCycles: Int
    public let stagger: Double
    public let out: URL
    public let loopRepeatCount: Int
    // --- chunking (D1′: frame-count chunks) ---
    public let checkpointIntervalFrames: Int   // chunk size in GLOBAL frames; default 30
```

```swift
private static func sanitizedStem(_ out: URL) -> String {
```

### 4.5 `renderFramesInterleaved` (NEW) — the byte-identical per-frame loop

A NEW `private` method on `ExportCoordinator`, used ONLY by `runResumableBody`. It
renders each global frame in `range` ONCE via `renderImage` and appends it `reps`×
inline (`reps = loopRepeatCount` for a loop frame, `1` for a transition frame), at a
running local `outputIndex` (the chunk's encoder session starts at PTS 0). Per-frame
cancel AND pause checks (single site — D5). It does NOT build the per-segment cache
that `renderFrames` repeat>1 does — so it is O(1) memory and chunkable at any frame
boundary.

```swift
private func renderFramesInterleaved(
    plan: FramePlan, params: RenderParams, budget: MetalRenderer.ThreadSeedBudget?,
    useMetal: Bool, range: Range<Int>, loopRepeatCount: Int,
    into encoder: VideoEncoder, globalRendered: inout Int, total: Int,
    yield: @Sendable (ExportProgress) -> Void
) async throws {
    let start = ProcessInfo.processInfo.systemUptime
    var outputIndex = 0
    for gf in range {
        if cancelled || Task.isCancelled { throw ExportError.cancelled }
        if paused { throw ExportError.paused }
        let d = plan.descriptor(for: gf)
        let img = try await renderImage(descriptor: d, plan: plan, params: params,
                                        budget: budget, useMetal: useMetal)
        renderCallCount += 1
        let reps = (d.kind == .loop) ? max(1, loopRepeatCount) : 1
        for _ in 0..<reps {
            try await encoder.append(img, atFrame: outputIndex)
            outputIndex += 1
            appendedFrameCount += 1
        }
        globalRendered += 1
        let elapsed = ProcessInfo.processInfo.systemUptime - start
        yield(ExportProgress(phase: .rendering, currentFrame: globalRendered,
                             totalFrames: total, elapsed: elapsed,
                             renderFPS: elapsed > 0 ? Double(globalRendered) / elapsed : 0))
    }
}
```

**Byte-identity (the load-bearing claim, pinned in §9.1):** for a loop segment this
emits `img_gf` `loopRepeatCount`× consecutively (`img_0×R, img_1×R, …`) — exactly what
`renderFrames` repeat>1's cache-replay emits
(`for img in cache { for _ in 0..<R { append } }`, `:281–287`). For a transition it
emits each frame once — exactly what `renderFrames` repeat>1's transition branch emits
(`:290–308`). Each global frame is rendered ONCE (`renderCallCount` once per `gf`),
so the v0.5.0 render-once speedup is **preserved** — the cache was never about avoiding
re-render within a run, only about writing the bytes `repeatCount×`; this writes them
`repeatCount×` too, just inline. The ONLY difference from `renderFrames` is WHEN the
appends happen (inline vs after the segment cache fills) — the bytes and order are
identical. Crucially, `reps` is decided **per global frame** from `d.kind`, so a chunk
range that spans a loop→transition boundary is handled correctly (loop frames ×R,
transition frames ×1) — the F2 bug that forbids frame-count chunking of the EXISTING
`renderFrames` repeat>1 path does not exist here. The existing `renderFrames` is
UNCHANGED (no `pausable` flag, no new branch); all existing byte-identity pins stay
green.

`renderCallCount`/`appendedFrameCount` increment exactly as `renderFrames` does
(`renderCallCount` once per `gf`; `appendedFrameCount` once per encoder append) so the
`LoopRepeatTests`-style seams (`:36–40`) stay meaningful.

```swift
    case .paused(let out, _, _):                   // cancel-from-paused = discard + done
```

## 8. Risks & mitigations

| Risk | L/I | Mitigation |
|---|---|---|
| Resume non-byte-identical frames (rule #2 break) | M/H | Rebuild `Schedule`+`FramePlan`+`ThreadSeedBudget(baseSeed: params.seed)` identically; re-parse sources from hash-verified bytes via the same `Flam3Parser` path. Pin: decode paused-resumed output vs no-pause output → pixel-identical (max-abs-diff 0). |
| **`renderFramesInterleaved` diverges from `renderFrames` output** (the F2 headline) | **H/H** | Traced byte-for-byte: loop frames emitted `loopRepeatCount`× consecutively, transition frames once — identical to `renderFrames` repeat>1. Pinned at `loopRepeatCount == 1` AND `== 2`: a full-timeline `renderFramesInterleaved` render decodes pixel-identical to `run` of the same job. |
| `renderFramesInterleaved` is new code (regression risk for the resumable path) | M/M | It is a self-contained per-frame loop reusing `renderImage`/`VideoEncoder`/`FramePlan`; the existing `renderFrames`/`runJob`/`runLongForm`/`runBatch` are untouched (no `pausable` flag) → their byte-identity pins stay green and isolate the risk. |
| Checkpoint corrupt/unreadable | M/H | Resilient read (corrupt ⇒ restart from chunk 0 with a notice; never crash). `ExportError.checkpointUnreadable`. |
| Checkpoint schema from a newer/older version | L/M | `schemaVersion` gate (D12): mismatch ⇒ ignore + fresh start; never crash. |
| Source genome file changed between pause and resume | L/H | SHA-256 on resume → `.checkpointSourceChanged` (clear failure, terminal). |
